1. 什么是 Metasploit Framework

Metasploit Framework（简称 MSF）是一个开源的渗透测试框架，由 H.D. Moore 于 2003 年创建，目前由 Rapid7 公司维护。它集成了数千个已知漏洞的利用代码，是安全研究人员和渗透测试工程师最常用的工具之一。

MSF 的核心价值在于模块化设计：它将渗透测试的各个环节（信息收集、漏洞利用、后渗透、权限维持等）封装成独立的模块，使用者只需组合这些模块即可完成复杂的攻击链条，无需从零编写代码。

MSF 的主要特点：

  • 模块化架构：所有功能以模块形式存在，按需加载，灵活组合
  • 活跃的社区支持：全球安全研究者持续贡献新的漏洞利用模块
  • 易于扩展：支持使用 Ruby 语言编写自定义模块
  • 跨平台：支持 Linux、Windows、macOS 等操作系统
  • 丰富的 Payload 库：内置多种类型的载荷，满足不同场景需求

3. MSF 核心概念与模块体系

理解 MSF 的模块体系是学习的关键。MSF 将渗透测试拆分为多个环节，每个环节对应一类模块。

3.1 六大核心模块

（1）Exploit（漏洞利用模块）

作用：触发目标系统的漏洞，获取访问权限。

Exploit 是渗透测试的核心模块。它包含针对特定漏洞的攻击代码，例如著名的 MS17-010（永恒之蓝）漏洞利用模块。

模块路径示例：exploit/windows/smb/ms17_010_eternalblue

通俗理解：Exploit 相当于”钥匙”，用于打开目标系统的”门锁”（漏洞）。

（2）Payload（载荷模块）

作用：漏洞利用成功后，在目标系统上执行的代码。

Payload 决定了你获得目标控制权后以什么方式与目标通信。最常见的 Payload 是反弹 Shell（Reverse Shell），即让目标主机主动连接攻击者的机器。

常见 Payload 类型：

Payload 类型 说明
windows/meterpreter/reverse_tcp Windows 反弹 Meterpreter（TCP）
windows/meterpreter/reverse_https Windows 反弹 Meterpreter（HTTPS，更隐蔽）
linux/x64/meterpreter/reverse_tcp Linux 64位反弹 Meterpreter
windows/x64/shell/reverse_tcp Windows 反弹普通 Shell
php/meterpreter/reverse_tcp PHP 反弹 Meterpreter

通俗理解：Payload 相当于”快递员”，Exploit 打开门后，Payload 进入目标系统并建立与你的通信通道。

（3）Auxiliary（辅助模块）

作用：用于信息收集、扫描、漏洞验证等辅助任务。

Auxiliary 模块不会直接攻击目标，而是帮助你了解目标系统的情况。

常用 Auxiliary 模块：

模块 用途
auxiliary/scanner/portscan/tcp TCP 端口扫描
auxiliary/scanner/smb/smb_version SMB 服务版本探测
auxiliary/scanner/ssh/ssh_login SSH 弱口令爆破
auxiliary/scanner/http/dir_scanner Web 目录扫描
auxiliary/scanner/ftp/ftp_login FTP 弱口令测试

通俗理解：Auxiliary 相当于”侦察兵”，在发动攻击前帮你摸清目标的情况。

（4）Post（后渗透模块）

作用：在获得目标控制权后，执行进一步的操作。

当你已经拿下了目标主机的 Shell，Post 模块可以帮助你收集信息、提升权限、横向移动等。

常用 Post 模块：

模块 用途
post/windows/gather/hashdump 抓取 Windows 密码哈希
post/windows/manage/migrate 进程迁移
post/multi/recon/local_exploit_suggester 本地提权建议
post/windows/gather/enum_logged_on_users 枚举登录用户
post/linux/gather/hashdump 抓取 Linux 密码哈希

通俗理解：Post 相当于”内应”，进入目标后帮你搜集情报、巩固控制。

（5）Encoder（编码器模块）

作用：对 Payload 进行编码/混淆，绕过杀毒软件和防火墙的检测。

MSF 中最著名的编码器是 shikata_ga_nai（日语：仕方がない，意为”没办法”），它使用多态 XOR 编码技术，每次生成的 Payload 都不同。

通俗理解：Encoder 相当于”伪装面具”，让 Payload 改头换面，躲过安检。

（6）NOP（空指令模块）

作用：生成空指令（No Operation），用于填充 Payload 以确保在缓冲区溢出攻击中稳定执行。

通俗理解：NOP 相当于”填充物”，确保 Payload 在内存中正确对齐。

MSF 的模块路径遵循统一的命名规则：

5.3 search 命令详解

search 是 MSF 中使用最频繁的命令之一，它帮你从数千个模块中快速找到需要的模块。

Rank（等级）说明：MSF 为每个模块标注了质量等级，从高到低：

  • excellent：成功率极高，几乎不会导致目标崩溃
  • great：成功率较高，有自动目标检测
  • good：成功率中等，需要手动指定目标
  • normal：普通模块
  • average：一般
  • low：成功率较低

关键参数说明：

参数 含义 说明
RHOSTS 目标主机地址 可填单个 IP 或 IP 段，如 192.168.1.100 或 192.168.1.0/24
RPORT 目标端口 目标服务监听的端口
LHOST 攻击者主机地址 你的机器 IP，反弹 Shell 时目标会连接这个地址

13.3 Payload 无法上线

可能原因及解决方法：

  1. 网络不通：确认攻击机和目标机可以相互通信（ping 测试）
  2. 防火墙拦截：临时关闭目标防火墙或更换端口（如使用 443 端口伪装 HTTPS 流量）
  3. Payload 架构不匹配：确认目标系统是 32 位还是 64 位，选择对应的 Payload
  4. LHOST 设置错误：确认 LHOST 是攻击机的 IP 地址，且目标能够访问到

13.5 会话意外断开
