CTF - sql注入

一．定义

SQL注入（SQL Injection）：是一种将恶意SQL代码插入到应用程序输入参数中的攻击技术，攻击成功后可以获取、篡改或删除数据库数据，甚至控制服务器。

比如使用单引号来破坏SQL的闭合结构。

根本原因：未做参数化，直接拼接用户可控输入。

预编译会预防的原因：SQL 结构先编译固定，用户输入仅作为数据，不会改变语句结构。

分类以及判断方式

  • 数字型注入：判断方法：使用 1 and 1=1，1 and 1=2 来判断。当输入 and 1=1 时页面显示正常，and 1=2 时页面显示异常。
  • 字符型注入：判断方法：使用 1' and '1'='1，1' and '1'='2 来判断。当输入 1' and '1'='1 时页面显示正常；1' and '1'='2 时页面显示异常。

二、注入方式

联合注入

注：在联合注入的过程中，记得最后加注释符，其中 -- 和 #（单行注释符）都可以，其中 -- 适用范围更广。

一．用 order by 子句确定数据表字段数。 输入 id=1' order by 1 --+

注：order by N 是SQL的排序语句，N 代表按第N个字段排序。

以此来确定字段数的最大值，比如字段数的长度为2，则输入2的时候正常，3的时候则报错。

二．字段数确定后，需构造 union select 语句提取数据库信息。 大致步骤为：

  1. 让原查询无结果：将 id 值改为 -1（如 id=-1'），使原查询返回空，触发 union 查询的结果显示。
  2. 匹配字段数拼接查询：按2个字段构造语句，如输入 id=-1' union select 1,2 --+。假如说执行后页面会显示1和2，说明第1、2个字段是可显示位，后续将占位符替换为查询函数即可。
  3. 提取基础数据库信息：id=-1' union select 1,database() --+，其中括号是函数的语法特征，用于标识这是一个函数调用，而非普通的字段名或变量。
  4. 提取 security 数据库的所有表名：?id=-1' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()--（这里的database要换成对应的库名，如 'sqli'）

注：

  • information_schema.tables 是MySQL的系统元数据表，存储了所有数据库中所有表的基本信息。
  • where table_schema=database() 是筛选条件：仅查询当前数据库下的表。
  • table_name 是系统表字段，代表”表名”。
  • group_concat() 将所有表名拼接成一个字符串，解决分页显示问题，直接看到全部结果。
  1. 提取列名：-1 union select 1,2,group_concat(column_name) from information_schema.columns where table_name='users'（一样，Users要换成对应的表名）

注：

  • information_schema.columns 是MySQL的系统元数据表，存储所有数据库中所有表的字段信息。
  • where table_name='users' 指筛选条件：仅查询 users 表的字段。
  • column_name 是系统表字段，代表”字段名”。
  1. 提取 users 表的全量账号密码（爆flag）：-1 union select 1, group_concat(列名) from 表名

注：若为文件导出注入，则在后面加 into outfile "D:/自定义文件名"--+

其中，into outfile：MySQL的文件导出关键字，作用是将 select 查询的结果写入指定路径的文件中；D:/ 是磁盘根目录。

报错注入

当数据库不显示正常查询结果，但会显示报错信息时可使用报错注入。

常用函数：extractvalue，updatexml，group by，利用数据库报错直接带出数据。

extractvalue报错注入

  • ❤ 爆破数据库名

  • ❤ 爆破表格名

  • ❤ 爆破字段名

  • ❤ 爆破字段值（flag）

updatexml报错注入

逐步拆解：

  1. updatexml(1,2,1)--+
  2. 拼接函数 concat(0x7e,3,0x7e)
  3. SQL查询关键字（select username/password from users limit 0,1）

  • ❤ 爆破数据库名

  • ❤ 爆破表格名

    使用 LIMIT 0, 1 是为了防止多行结果导致错误。

  • ❤ 爆破表格字段

  • ❤ 获取字段值

  • ❤ 爆破对应用户的密码

group by报错注入

  • ❤ 爆破数据库

  • ❤ 爆破出所有数据库表格

  • ❤ 爆破字段名

  • ❤ 爆破字段值

  • ❤ 爆破用户密码

盲注

概念：在SQL注入过程中，SQL语句执行查询后，查询数据不能回显到前端页面中，我们需要使用一些特殊的方式来判断或尝试（说白了就是猜测内容），这个过程称为盲注。

  • 布尔盲注：根据页面真假判断数据。
  • 时间盲注：无回显，用 sleep 延时判断。

布尔盲注

  1. 猜解当前数据库名的长度：构建URL：1 and length(database())=所猜测的域名长度 --+
    例如 security 猜测的域名长度为8。

  2. 逐位猜测数据库的字符以确定数据库的名称：... and ascii(substr(database(),1,1))=ascii编译前的数字--+

    逐步拆解：substr(string, start, length) 的参数分别指字符串，起始位置，长度。

    • ascii(substr(2,1,1))
    • 数据库 database()

  3. 确定数据库的名称后，尝试爆破出users表名：... and ascii(substr((select username from security.users limit 0,1),1,1))=115--+（即猜测的第一个字符为s）

    然后逐一尝试。

时间盲注

  • 注入类型：字符型GET注入，无数据回显，仅能通过时间延迟判断SQL语句执行结果。

  • 验证注入点：?id=1' and sleep(5) --+ 若页面响应延迟5秒，说明存在单引号闭合的时间盲注漏洞。一般来说后端是单引号、双引号、括号+引号的闭合方式。

  • 猜解数据库名长度：例如 ?id=1' and if(length(database())=8,sleep(5),1) --+ 延迟则证明当前数据库名长度为8。

注：if(condition, true_value, false_value) 是MySQL条件函数，这是基于时间的盲注关键部分；length(database())=8 是条件判断内容，代表数据库的长度为8；sleep(5) 指条件为真时的执行，代表如果该条件成立，则延迟5秒；1 指条件为假时的执行，指如果长度≠8，即该条件不成立，返回1（正常执行）。

  • 逐字符猜解数据库名：示例（猜第一个字符）：?id=1' and if(ascii(substr(database(),1,1))=115,sleep(5),1) --+ 若延迟5秒，则说明数据库名称第1个字符为s。

  • 猜解表名与字段：猜解表名，例如 ?id=1' and if(substr((select table_name from information_schema.tables where table_schema=database() limit 3,1),1,1)='u',sleep(5),1) --+ 即为猜解出第4个表名。

  • 猜解 username/password 字段：通过 information_schema.columns 系统表，与布尔盲注的方式相同。

堆叠注入

概念：堆叠注入，也称堆查询注入，顾名思义就是多条语句同时执行。在SQL中，分号 ; 用来表示一条SQL语句的结束。

原理：很简单，mysql_multi_query() 支持多条SQL语句同时执行。

二次注入

二次注入概念：二次注入是指已存储（数据库、文件）的用户输入被读取后再次进入到SQL查询语句中导致的注入。二次注入是SQL注入的一种，但是比普通SQL注入利用更加困难，利用门槛更高。普通注入数据直接进入到SQL查询中，而二次注入则是输入数据经处理后存储，取出后，再次进入到SQL查询。

宽字节注入

宽字节注入的核心是利用多字节字符集的编码特性，将 addslashes() 插入的转义反斜杠”吃掉”，使单引号重新生效。

原理：其核心在于 addslashes() 函数在用户输入转义时，会在单引号前加斜杠（\'），但如果我们使用宽字节时，斜杠会和之前的宽字节共同被识别为一个高位字符，从而让未被转义的单引号被识别，闭合SQL语句。

Cookie注入点

定义：普通的SQL注入是把恶意代码放在URL里（?id=1'），而Cookie注入是把恶意代码放在Cookie里。

程序员只防护了URL参数，忘记了防护Cookie，并且Cookie也会被后端接收并拼接到SQL语句中，这就造成了该漏洞。

注入过程：

首先查看Cookie：

  1. 按 F12 打开开发者工具。
  2. 点击 Application（应用程序）标签（储存中）。
  3. 左边找到 Cookies，点击当前网址。
  4. 就能看到所有Cookie。
    （当然也可以直接BP抓包，然后查看）

然后修改Cookie：
主要通过HackBar来进行Cookie修改（BP也可以），主要通过修改Cookie值来达到攻击的效果，攻击方法可以使用报错，也可以使用联合查询，具体攻击方式依题判断。

注：

  • LoadURL：下载当前网址到HackBar上，这个可以省去复制的麻烦。
  • Cookie：Cookie值的修改，也是一个注入点，就和输入框一样，可以在这里进行报错或者联合查询的注入（注：前面必须加上 id=）。
  • Execute：进行攻击尝试。

UA注入点

定义：UA（User-Agent），即用户代理，是浏览器访问网站时发送的”自我介绍”，告诉服务器”我是用什么浏览器访问的”。

UA注入点存在的原因和Cookie注入点一样，即UA可以直接拼接到SQL语句中，且不做任何处理。

所以，我们可以通过修改UA的值，来实现攻击的目的。

注入过程：
和Cookie注入点一样，打开HackBar或者使用BP来修改UA的值，并结合报错（主要）、联合查询等方式来进行攻击。

注：无论是Cookie还是UA、Referer，先判断类型，如果是数字型的话就不用注释，如果是字符型则需要注释。

Referer注入点

定义：Referer 是 HTTP 请求头中的一个字段，告诉服务器”我是从哪个页面跳转过来的”。

产生Referer注入的原因也跟前两者一样，通过直接把Referer拼到SQL语句中，从而达到攻击的目的。

攻击方式与前两者相同，在HackBar进行攻击。

过滤空格

当目标网站或靶场环境中过滤了空格字符后，我们可以使用以下几种方式来绕过限制：

  1. 使用 + 号替代空格：例如，union+select+1,2,3。
  2. URL编码替代：%20（空格）、%09（水平制表符HT）、%0A（换行符LF）、%0C（换页符FF）、%0D（回车CR）、%0B（垂直制表符VT）、%A0（不间断空格NBS）。
  3. 使用SQL注释符 /**/ 替代空格，如：union/**/select。
  4. 括号 () 替代空格：select(database())。
  5. 使用报错注入技巧绕过限制。
