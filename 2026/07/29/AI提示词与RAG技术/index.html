AI提示词与RAG技术

AI 学习笔记：提示词工程与 RAG 检索增强生成

本笔记梳理了「如何高效向 AI 提问」以及「RAG（检索增强生成）技术」的完整知识体系，从问题出发，逐步推导出解决方案，适合零基础学员复习回顾。

一、如何向 AI 提问：提示词工程

与 AI 大模型交互时，提示词（Prompt）的质量直接决定回答的质量。一个标准的、高质量的提示词通常包含四个核心要素：

要素 含义 作用 示例
角色（Role） 给 AI 设定一个身份 引导 AI 从特定专业视角思考和回答 “你是一位资深的小学数学老师”
任务（Task） 明确告诉 AI 要做什么 让 AI 聚焦于核心目标，避免跑题 “请讲解分数加减法的计算方法”
上下文（Context） 提供背景信息或参考资料 帮助 AI 理解场景，给出更贴合实际的回答 “听众是刚接触分数的三年级学生，需要用生活化的例子”
要求（Requirement） 规定输出的格式、风格、限制等 让结果更符合使用预期，便于直接使用 “分步骤讲解，每步配一个例子，最后总结要点，字数 500 字以内”

完整示例：

你是一位资深的小学数学老师（角色）。请讲解分数加减法的计算方法（任务）。听众是刚接触分数的三年级学生，需要用生活化的例子帮助他们理解（上下文）。请分步骤讲解，每步配一个例子，最后用三句话总结要点，字数控制在 500 字以内（要求）。

小结： 提示词越精准、要素越完整，AI 的回答就越专业、越可用。

二、大模型的局限性与「幻觉」问题

2.1 公有大模型的优势与短板

公有大模型（如 GPT、文心一言、通义千问等）在训练时吸收了海量的公开数据，知识面非常广。但它有一个根本性的短板：

公有大模型的训练数据虽然丰富，却缺乏企业/个人的「私有专属知识」。

这些私有知识包括：企业内部文档、产品手册、业务数据、个人笔记等——它们从未出现在大模型的训练语料中。

2.2 什么是「幻觉」

当用户询问涉及私有知识领域的问题时，大模型由于不具备这些知识，却又要”努力给出一个答案”，于是会：

一本正经地胡说八道——编造看似合理但实际上完全错误的内容。

这种现象在 AI 领域被称为 「幻觉」（Hallucination）。

幻觉的危害： 表面上答案流畅、自信，极具迷惑性，但如果用户不加分辨地采信，可能导致严重的错误决策（尤其在医疗、法律、金融等专业领域）。

三、RAG：检索增强生成——解决幻觉的钥匙

3.1 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成） 是一种通过”先检索、后生成”来增强大模型回答能力的技术。

3.2 RAG 的核心思想

关键点： RAG 不让大模型”凭记忆”回答，而是先从外部知识库中检索出与问题相关的真实信息，再让大模型基于这些检索到的内容生成答案。这样一来，回答就有了事实依据，从而有效避免幻觉。

3.3 为什么 RAG 能解决幻觉

对比维度 纯大模型 RAG 增强
知识来源 仅依赖训练时记住的数据 实时从外部知识库检索
私有知识 不具备 可通过私有知识库提供
回答依据 凭”记忆”生成 基于检索到的真实文档
幻觉风险 高 显著降低

四、构建私有知识库：RAG 的完整流程

要使用 RAG，首先需要构建一个私有知识库。整个流程分为两大阶段：知识库构建阶段（建库） 和 问答检索阶段（使用）。

阶段一：知识库构建（一次性 / 增量更新）

Step 1：收集资料

准备作为知识库来源的原始资料，例如：

  • 企业内部文档（PDF、Word、TXT、Markdown 等）
  • 产品手册、FAQ、技术规范
  • 业务数据、培训材料等

Step 2：数据清洗

对原始资料进行预处理，清除无用的、干扰性的数据，例如：

  • 去除乱码、特殊字符、页眉页脚
  • 删除空内容、重复内容、无关的图片说明
  • 统一格式，保证数据质量

清洗的目的是让后续处理更高效、检索更准确。

Step 3：数据分块（Chunking）

将清洗后的长文本切分成若干个数据块（Chunk），便于向量化和检索。常见的分块策略有：

分块方式 说明 适用场景
固定大小切分 按固定字符数/Token 数切分 简单快速，适合格式统一的文本
句子切分 以句子为单位切分 需要保持语义完整性的场景
段落切分 以段落为单位切分 段落结构清晰的文档
递归切分 按层级递归切分（先段落→句子→字符） 结构复杂的混合文档，兼顾语义与大小
语义相似度切分 根据语义相似度动态切分 对语义连续性要求高的场景

为什么要分块？ 大模型有输入长度限制；同时，小块文本向量化后检索更精准，能定位到最相关的片段。

Step 4：向量化（Embedding）+ 存入向量数据库

  1. 向量化： 使用 Embedding 模型，将每个数据块转换为一个高维向量（一串数字），这串向量捕捉了文本的语义信息。语义越相近的文本，向量在空间中的距离越近。
  2. 存入向量数据库： 将数据块及其对应的向量，存放到向量数据库的特定位置中，建立起可供检索的”语义索引”。

向量数据库是专门用于存储和检索向量的数据库（如 FAISS、Milvus、Chroma、Pinecone 等），能根据向量相似度快速找到最相关的内容。

阶段二：问答检索（每次用户提问时执行）

Step 5：用户提问 → 向量化 → 检索

  1. 用户提出问题
  2. 用同一个 Embedding 模型对问题进行向量化
  3. 将问题向量发送到向量数据库
  4. 通过相似度计算（如余弦相似度），检索出与问题最相关的若干个数据块

Step 6：构建新 Prompt → 生成回答

将用户的问题与检索到的知识内容组合，构建一个新的 Prompt，交给大模型：

大模型基于这些”现查现用”的真实资料生成回答，最终响应用户。

此时大模型不再”凭空想象”，而是”开卷考试”，回答有据可依，幻觉问题得到有效控制。

五、构建过程中的常见问题与解决方案

5.1 表格处理问题

问题描述： 在对包含表格的文档进行分块时，容易出现表头丢失的情况。比如一个大表格被切分到不同的数据块中，后续的块只保留了表格数据，却没有表头，导致 AI 无法正确理解每一列数据的含义，从而识别失败、检索错误。

解决方案：

  1. 先提取表格内容再分块： 在分块之前，先对文档中的表格进行专门识别和提取，将表格转换为结构化的文本（如 Markdown 表格、JSON、键值对等），保证表头与数据始终绑定在一起。
  2. 使用工具进行适配： 借助专业的文档解析工具（如表格识别解析器），在数据清洗阶段就将表格正确解析出来，作为完整的语义单元处理，避免被机械切分。

核心原则： 表格的表头与数据是一个整体，分块时不能割裂，必须保证语义的完整性。

5.2 其他常见问题（拓展了解）

问题 说明 应对思路
检索不准 检索到的内容与问题相关性低 优化分块策略、调整 Embedding 模型、增加重排序（Rerank）
分块过大/过小 块太大检索不精准，块太小丢失上下文 选择合适的分块大小，可设置块间重叠（Overlap）
知识更新滞后 知识库内容过时 定期增量更新知识库

六、知识总结

本节课的核心知识链路可以用一句话串联：

因为提示词决定了提问质量，而公有大模型缺乏私有知识会产生幻觉，所以我们用 RAG 技术——先构建私有知识库（收集→清洗→分块→向量化→入库），再在问答时检索相关知识并构建新 Prompt让大模型有据可依地回答，从而有效解决幻觉问题；构建中还需注意表格等特殊结构的处理，保证语义完整。

关键词速记：

  • 提示词四要素：角色 + 任务 + 上下文 + 要求
  • 幻觉（Hallucination）：大模型一本正经地胡说八道
  • RAG = 检索（Retrieval）+ 增强（Augmented）+ 生成（Generation）
  • 知识库构建五步：收集 → 清洗 → 分块 → 向量化 → 入库
  • 问答检索三步：问题向量化 → 检索 → 构建 Prompt 生成回答
  • 分块策略：固定大小 / 句子 / 段落 / 递归 / 语义相似度
  • 表格处理：先提取表头与数据，保证完整性
