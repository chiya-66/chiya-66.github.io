网络通信模型 · 传输层核心协议 · DoS攻击

第一部分：网络通信模型

1.1 什么是网络通信模型？

网络通信模型就是一套"规则"或"框架"，用来规定计算机之间如何传递数据。就好比两个人写信：需要信封格式、地址写法、邮局分拣流程等规则。网络模型将这些规则分层管理，每一层只管自己的事情，便于设计和维护。

1.2 OSI 七层模型（理论参考模型）

OSI（Open System
Interconnection）是国际标准化组织（ISO）制定的网络通信模型，共分7层。下面从上到下逐一说明：

  • 第7层 — 应用层（Application Layer）

直接为用户提供网络服务，如浏览器（HTTP）、邮件（SMTP）、文件传输（FTP）。这是用户接触最多的一层。

  • 第6层 — 表示层（Presentation Layer）

负责数据格式转换、加密解密、压缩解压。确保不同系统之间的数据能被正确理解。例如：图片的JPEG编码、文本的ASCII/Unicode编码。

  • 第5层 — 会话层（Session Layer）

负责建立、管理和拆除会话（Session），即两台设备之间的通信会话。例如：登录一个网站时建立的会话。

  • 第4层 — 传输层（Transport Layer）

⭐ 核心层！负责端到端的通信，保证数据可靠或快速地交付。主要协议有
TCP（可靠）和 UDP（快速）。这层是本文第二部分重点。

  • 第3层 — 网络层（Network Layer）

负责数据包的路由和转发，决定数据从源到目的地的路径。核心设备是路由器，核心协议是
IP（网际协议）。

  • 第2层 — 数据链路层（Data Link Layer）

负责在物理链路上进行可靠的数据传输，进行差错检测和流量控制。核心设备是交换机。数据单元称为"帧"（Frame）。

  • 第1层 — 物理层（Physical Layer）

负责传输原始的比特流（0和1），定义电压、线缆规格、接口形状等物理特性。核心设备是集线器（Hub）、中继器。

💡 记忆口诀（从上到下）："应-表-会-传-网-数-物" →
"应表会传网数物" → 谐音记忆："应该会穿网速快"

1.3 TCP/IP 四层模型（实际使用模型）

TCP/IP 模型是互联网实际使用的模型，比OSI更简洁，共4层：

  • 第4层 — 应用层

对应 OSI 的应用层、表示层、会话层。协议有 HTTP、HTTPS、FTP、SMTP、DNS
等。

  • 第3层 — 传输层

对应 OSI
的传输层。核心协议：TCP（传输控制协议）、UDP（用户数据报协议）。

  • 第2层 — 网际层（Internet Layer）

对应 OSI 的网络层。核心协议：IP（IPv4 / IPv6）、ICMP、ARP。

  • 第1层 — 网络接口层（Network Access Layer）

对应 OSI 的数据链路层和物理层。负责在物理网络上发送数据。

1.5 数据封装与解封装

当数据从一台计算机发送到另一台时，每一层都会给数据加上自己的头部信息，这个过程叫"封装"（Encapsulation）。接收方则逐层去掉头部，叫"解封装"（Decapsulation）。

数据在各层的叫法不同：

  • 应用层 → 数据（Data / Message）

  • 传输层 → 数据段（Segment，TCP）/ 数据报（Datagram，UDP）

  • 网络层 → 数据包（Packet）

  • 数据链路层 → 数据帧（Frame）

  • 物理层 → 比特流（Bits）

第二部分：传输层核心协议

2.1 传输层的作用

传输层位于网络层之上、应用层之下，负责为应用程序提供"端到端"的通信服务。它的核心任务是：

  • 端口寻址：区分同一台主机上的不同应用程序（通过端口号，如 HTTP→80,
    HTTPS→443）

  • 数据分段与重组：将应用层的大数据切分成小段，接收方再拼回去

  • 可靠性控制：保证数据不丢失、不重复、不乱序（TCP）

  • 流量控制：协调发送方和接收方的速率

  • 差错控制：检测和纠正传输中的错误

2.2 TCP（传输控制协议）—— 可靠但慢

TCP（Transmission Control
Protocol）是面向连接的、可靠的数据传输协议。就像"打电话"：先拨号建立连接，然后通话，最后挂断。

2.2.1 TCP 的特点

  • 面向连接：通信前必须先建立连接（三次握手），结束后断开连接（四次挥手）

  • 可靠传输：通过确认应答（ACK）、超时重传、序列号等机制，确保数据完整到达

  • 有序传输：数据按发送顺序到达接收方

  • 流量控制：使用滑动窗口机制，避免发送方太快导致接收方来不及处理

  • 拥塞控制：当网络拥堵时主动降低发送速率，避免网络瘫痪

2.2.2 三次握手（建立连接）

三次握手是 TCP 建立连接的过程，共三个步骤：

  • 第1次（SYN）：客户端 → 服务器，发送 SYN=1
    的报文，表示"我要和你建立连接"

  • 第2次（SYN+ACK）：服务器 → 客户端，发送 SYN=1,
    ACK=1，表示"收到，我也准备好和你连接"

  • 第3次（ACK）：客户端 → 服务器，发送 ACK=1，表示"好的，连接已建立"

为什么要三次？防止已经失效的连接请求突然又传到服务器，造成错误。三次握手能确保双方都具备收发能力。

2.2.3 四次挥手（断开连接）

四次挥手是 TCP 断开连接的过程：

  • 第1次（FIN）：客户端 → 服务器，表示"我的数据发完了，可以关闭了"

  • 第2次（ACK）：服务器 → 客户端，表示"收到你的关闭请求"

  • 第3次（FIN）：服务器 → 客户端，表示"我的数据也发完了，可以关闭了"

  • 第4次（ACK）：客户端 → 服务器，表示"好的，关闭连接"

为什么是四次？因为 TCP 是全双工通信，双方都要单独关闭自己的数据通道。

2.2.4 TCP 报文头部结构

TCP 头部至少 20 字节，重要字段包括：

  • 源端口 / 目的端口（各2字节）：标识应用程序

  • 序列号（4字节）：保证数据顺序

  • 确认号（4字节）：告诉对方下一个期望收到的序号

  • 标志位（6位）：SYN（建立连接）、ACK（确认）、FIN（断开）、RST（重置）、PSH（推送）、URG（紧急）

  • 窗口大小（2字节）：用于流量控制

2.3 UDP（用户数据报协议）—— 快速但不可靠

UDP（User Datagram
Protocol）是无连接的、不可靠的数据传输协议。就像"寄明信片"：直接扔进邮筒，不关心是否到达。

2.3.1 UDP 的特点

  • 无连接：不需要建立连接，直接发送数据

  • 不可靠：不保证数据到达，没有确认和重传机制

  • 开销小：头部仅 8 字节（TCP 至少 20 字节）

  • 速度快：没有握手、确认、重传等流程

  • 支持广播和多播：一对一多的通信场景

2.3.2 UDP 的应用场景

  • 视频直播 / 视频会议：偶尔丢一帧不影响，但延迟不能高

  • 在线游戏：实时性要求高，丢包可以忍受

  • DNS 查询：一次查询一个请求一个应答，简单快速

  • VoIP 网络电话：实时语音通信

2.4 TCP 与 UDP 的对比总结

对比项 TCP UDP

连接方式 面向连接（三次握手） 无连接

可靠性 可靠（确认重传） 不可靠（尽力而为）

数据顺序 保证有序 不保证有序

速度 较慢 较快

头部大小 20~60 字节 8 字节

流量/拥塞控制 支持 不支持

典型应用 网页(HTTP)、邮件、文件传输 直播、游戏、DNS

**💡 简单记忆：**TCP = 可靠但慢（适合重要数据）；UDP =
快但可能丢（适合实时应用）

2.5 端口号

端口号用于标识一台主机上的不同应用程序，范围 0~65535。

  • 知名端口（0~1023）：HTTP=80, HTTPS=443, FTP=21, SSH=22, DNS=53

  • 注册端口（1024~49151）：分配给特定服务，如 MySQL=3306

  • 动态/私有端口（49152~65535）：临时分配给客户端使用

    第三部分：DoS 攻击（拒绝服务攻击）

3.1 什么是 DoS 攻击？

DoS（Denial of
Service，拒绝服务攻击）是一种通过消耗目标系统资源（带宽、CPU、内存、连接数等），使其无法正常为合法用户提供服务的攻击方式。

打个比方：一家餐厅只有10个座位，攻击者派了100个人进去占座但不点餐，真正的客人就没地方坐了。这就是拒绝服务。

3.2 DDoS 攻击 —— 分布式拒绝服务攻击

DDoS（Distributed Denial of Service）是 DoS
的升级版，攻击者控制大量"僵尸主机"（肉鸡）同时向目标发起攻击，威力更大、更难防御。就像上千人同时冲进餐厅占座。

  • 攻击者（Attacker）：幕后操控者

  • 控制服务器（C&C）：下发攻击指令

  • 僵尸网络（Botnet）：被控制的大量受害主机（肉鸡）

  • 目标（Target）：被攻击的服务器

3.3 常见的 DoS / DDoS 攻击类型

3.3.1 体积型攻击（Volumetric Attacks）

目标：消耗目标带宽。通过发送海量数据包，塞满目标网络带宽。

  • UDP Flood（UDP 洪泛）：向目标随机端口发送大量 UDP 包，使其忙于处理

  • ICMP Flood（ICMP 洪泛 / Ping Flood）：发送大量 Ping 请求

  • DNS 放大攻击（DNS Amplification）：利用 DNS
    服务器，发送小请求获取大响应，把流量放大几十倍打向目标

3.3.2 协议型攻击（Protocol Attacks）

目标：消耗服务器的连接资源或中间设备的处理能力。

  • SYN Flood（SYN 洪泛）：最经典的 DoS 攻击之一。攻击者发送大量 SYN
    包（三次握手的第一次）但不完成握手，导致服务器维护大量半开连接，耗尽连接表。

  • Smurf 攻击：向广播地址发送伪造源地址的 ICMP
    请求，导致大量回复涌向受害者。

  • ACK Flood：发送大量 ACK 包，迫使服务器进行无意义的处理。

3.3.3 应用层攻击（Application Layer Attacks）

目标：消耗应用服务器资源（CPU、内存）。模仿正常请求，更难检测。

  • HTTP Flood：大量请求网页、API 接口，耗尽服务器处理能力

  • Slowloris（慢速攻击）：发送不完整的 HTTP
    请求，保持连接打开，耗尽服务器连接池

  • DNS Query Flood：大量 DNS 查询请求，耗尽 DNS 服务器资源

3.4 SYN Flood 攻击详解（与传输层密切相关）

SYN Flood 是最常见也最具代表性的传输层 DoS 攻击，利用 TCP
三次握手的漏洞。

3.4.1 攻击原理

正常 TCP 三次握手：

  • ① 客户端发 SYN → 服务器

  • ② 服务器回复 SYN+ACK，并分配资源（进入 SYN_RCVD 状态）

  • ③ 客户端发 ACK，完成连接

SYN Flood 攻击：

  • 攻击者发送大量 SYN 包，但使用伪造的源 IP 地址

  • 服务器回复 SYN+ACK 到伪造的IP（无人回复）

  • 服务器一直等待 ACK，维护着大量半开连接

  • 服务器的"半开连接队列"（Backlog Queue）很快被填满

  • 后续正常的连接请求被丢弃，合法用户无法访问

3.4.2 SYN Flood 的防御方法

  • SYN Cookie：不分配资源，直到收到 ACK 才分配。将连接信息编码在 SYN+ACK
    的序列号中。

  • 增大半开连接队列（Backlog）大小

  • 缩短 SYN 超时时间

  • 部署专门的抗 DDoS 设备或云清洗服务（如 Cloudflare、AWS Shield）

3.5 其他与传输层相关的攻击

3.5.1 TCP 重置攻击（TCP RST Attack）

攻击者伪造 TCP 的 RST 包，强制断开两台主机之间的 TCP
连接。如果攻击者能正确猜测 TCP 序列号，就可以成功中断通信。

3.5.2 端口扫描（Port Scan）

虽然不是直接的 DoS
攻击，但常用于攻击前的信息收集。通过扫描目标主机的开放端口，了解其上运行的服务，为后续攻击做准备。

  • TCP 全连接扫描：完整完成三次握手来判断端口是否开放

  • SYN 半开扫描（隐蔽扫描）：只发送 SYN，根据回复判断端口状态

  • UDP 扫描：发送 UDP 包，根据 ICMP 不可达回复判断

3.6 如何防范 DoS / DDoS 攻击

  • 带宽扩容：增大出口带宽，提高攻击成本

  • 流量清洗：使用专业 Anti-DDoS 设备或云服务过滤恶意流量

  • 负载均衡：分散流量到多台服务器

  • 限制连接速率：对单个 IP 的连接数、请求频率进行限制

  • 防火墙规则：屏蔽异常流量、关闭不必要端口

  • CDN 加速：隐藏真实源站 IP，分散攻击流量

  • 监控告警：实时监控流量异常，及时发现并响应
