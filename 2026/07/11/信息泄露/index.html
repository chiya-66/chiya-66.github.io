信息泄露

  1. 目录遍历

    **定义：**目录遍历（Path Traversal / Directory
    Traversal），也叫路径穿越、文件读取漏洞，是Web常见高危漏洞。

    **原理：**用户可控参数直接拼接到文件路径，攻击者用  ../ 
    等向上跳转目录，读取服务器任意文件。

    基础payload：

    ../

    ../../

    ../../../../etc/passwd

    ../../../../c:/windows/win.ini

    绕过过滤：

    编码绕过：%2E%2E%2F （URL编码  ../ ）

    双重编码：%252E%252E%252F 

    平台兼容：..\ 、 ..\/ 

    截断绕过：file.txt%00 （旧版本PHP）

    嵌套：.…// → 解析为 ../

  2. Phpinfo

    **定义：**phpinfo() 是PHP内置的一个函数。当在PHP脚本中调用该函数时，它会生成一个详细的HTML页面，显示关于当前PHP环境的几乎所有配置信息。

    **phpinfo泄露的原理是：**开发者将包含 phpinfo() 函数的调试脚本遗留在生产环境的Web目录中，导致任何用户都能访问该页面，从而获取关于服务器PHP环境的极度敏感和详细的配置信息。

    **实战：**点击查看phpinfo

  1. Git泄露

    代码仓库未妥善配置，导致敏感信息（密码、密钥、接口、数据库配置）被提交上传到Git（GitHub/Gitee/GitLab）公开仓库

  1. Log

    当前大量开发人员使用git进行版本控制，对站点自动部署。如果配置不当,可能会将.git文件夹直接部署到线上环境。这就引起了git泄露漏洞。

    实战：

    查看源码，当看到git时，猜测有git的泄露

    我们可以尝试使用Hackgit进行攻击，输入指令

    python C:\Python27\Tools\GitHack-master\GitHack.py
    ...（填写网址）/.git

    1.进入 GitHack 克隆下来的目录

    首先先访问文件夹位置：cd
    C:\Python27\Tools\GitHack-master\dist\challenge-781ff6a0d097460f.sandbox.ctfhub.com_10800
    （其中cd指令便是切换到当前文件夹）

    2.然后执行git show指令，访问到flag

    show指令：**查看某一次提交（commit）的详细内容，包括改了哪些文件、具体改了什么代码、以及被删除的文件内容。而敏感信息（flag）可能就藏在这些内容里面

    2.Stash 

    当前大量开发人员使用git进行版本控制，对站点自动部署。如果配置不当,可能会将.git文件夹直接部署到线上环境。这就引起了git泄露漏洞。不过，Git
    是整个仓库的完整历史记录（包含所有提交过的文件），而 Stash
    只是临时保存的、还未提交的草稿。

    实战

  1. 第1步和前者一样，先通过扫描，扫描到敏感文件

  2. 先用cd指令定位该文件，然后输入git stash list、git stash pop


    height=”2.56875in”}

    注：

    git stash list —— 查看有没有”草稿”

    作用：列出所有临时储藏（Stash）的记录。

    CTF 出题人可能把 flag
    藏在开发人员临时保存但没提交的代码里，这个命令先看一眼有没有藏东西。

    git stash pop —— 恢复”草稿”

    作用：把最近一次储藏的草稿恢复到当前目录，并删除储藏记录。

    光看列表不知道内容，需要把文件”还原”出来，才能用 type 阅读。

    3.找到txt文件，然后通过type指令打开，获取flag，其中type指令为显示文本文件中的内容

  3. Index

    也是git泄露的一种类型，git log 看的是已提交的历史记录，git stash
    看的是临时保存的草稿，而index看的是已经 add 但还没 commit
    的暂存区文件。

    实战：跟log类型的Git泄露一样

  1. HG泄露

    当开发人员使用 Mercurial
    进行版本控制，对站点自动部署。如果配置不当,可能会将.hg
    文件夹直接部署到线上环境。这就引起了 hg 泄露漏洞。

    **注：**Mercurial 是一种轻量级分布式版本控制系统，采用 Python
    语言实现，易于学习和使用，扩展性强。其是基于 GNU General Public
    License (GPL) 授权的开源项目。

    在 Mercurial
    轻量级分布式版本控制系统中，本地既可以当做版本库的服务端，也可以当做版本库的客户端。版本库与工作目录不同，版本库存放了所有版本，而工作目录只是因为特定需要存放特定版本。与
    SVN 系统不同，SVN 的版本库集中在一台服务器中。这也导致很多初次使用
    Mercurial 系统的工作者，因为操作失误导致出现 HG 泄露漏洞的主要原因。

    **实战：**与之前的题目比较类似，同样使用 dvcs-ripper
    工具下载泄露的网站目录

    首先进行路径访问:cd /home/kali/Desktop/dvcs-ripper-master

    然后通过dvcs进行泄露的文件下载

    ./rip-hg.pl -u http://example.com/.hg

    (如果向下图一样发现提示404报错和两处完成，可能是没有完整下载网站目录）


    height=”0.5034722222222222in”}

    这时需要使用tree命令列出刚刚下载的.hg网站目录，发现可疑的文本文件

    tree .hg


    height=”2.2152777777777777in”}

    然后查看可疑的文本文件是否存在此题flag，发现历史版本

    cat .hg/last-message.txt

    发现历史版本可以使用进行关键字查找

    grep -a -r flag

    最后找到flag相关的txt文档，使用curl指令进行检查，得到flag
