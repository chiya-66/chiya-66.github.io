网络协议与技术入门指南

1. 网络基础概念

1.1 什么是网络协议？

网络协议就像人与人之间交流的"语言规则"。两个人要沟通，必须使用同一种语言（比如中文或英文）。计算机之间要通信，也必须遵守共同的"规则"，这些规则就是网络协议。

举个 🌰：你给朋友写信，需要：

  • 写收件人地址（IP地址的作用）

  • 写收件人姓名（端口号的作用）

  • 用信封包好（封装数据）

  • 通过邮局寄送（路由转发）

1.2 OSI 七层模型 vs TCP/IP 四层模型

  **OSI七层模型**       **TCP/IP四层模型**       **常见协议举例**

      应用层                  应用层              HTTP、DNS、FTP

      表示层                     ↑                    SSL/TLS

      会话层                     ↑                      ---

      传输层                  传输层                 TCP、UDP

      网络层                  网络层               IP、ARP、ICMP

    数据链路层              网络接口层                以太网

      物理层                     ↓                  网线、光纤

小白理解：数据从你的电脑发出，会经过一层层"包装"（就像寄快递要装箱、打包、贴单），到达目标后再一层层"拆开"。

1.3 IP 地址

  • IP地址 = 网络中的"门牌号"，用来唯一标识一台设备

  • IPv4：32位，如 192.168.1.1（常见格式）

  • IPv6：128位，如 2001:0db8:85a3::8a2e:0370:7334

  • 公网IP：全球唯一，可以在互联网上直接访问

  • 私网IP：局域网内使用，如 192.168.x.x、10.x.x.x、172.16.x.x

2. ARP 协议（地址解析协议）

2.1 什么是 ARP？

ARP（Address Resolution Protocol，地址解析协议）的作用是：根据 IP
地址找到对应的 MAC 地址。

2.2 为什么要用 ARP？

在局域网中，数据最终是通过 MAC地址（硬件地址）来传输的，而不是 IP 地址。

举个 ：

  • IP地址 = 一个人的"姓名"（方便人类记忆）

  • MAC地址 = 一个人的"身份证号"（硬件唯一标识）

  • ARP = 一个"通讯录"，通过姓名查到身份证号

2.3 ARP 工作流程

电脑A（IP: 192.168.1.10）想给 电脑B（IP: 192.168.1.20）发数据

↓

电脑A 不知道 电脑B 的 MAC 地址

↓

电脑A 广播发送 ARP请求："谁是 192.168.1.20？请告诉我你的MAC地址！"

↓

局域网内所有设备都收到这个广播

↓

只有 电脑B 回应："我是 192.168.1.20，我的MAC地址是
AA:BB:CC:DD:EE:FF"

↓

电脑A 收到回复，把 IP-MAC 对应关系存入 ARP缓存表

↓

下次再通信，直接查缓存，不用再广播了

2.4 ARP 缓存表

每台电脑都维护着一张 ARP缓存表，记录 IP 和 MAC 的对应关系。

在 Windows 上查看 ARP 缓存：

arp -a

示例输出：

接口: 192.168.1.10 --- 0x5
Internet 地址 物理地址 类型
192.168.1.1 aa-bb-cc-11-22-33 动态
192.168.1.20 aa-bb-cc-44-55-66 动态
192.168.1.255 ff-ff-ff-ff-ff-ff 静态

2.5 ARP 欺骗（安全知识）

ARP欺骗 是一种常见的网络攻击手段。

攻击原理：

攻击者冒充网关，告诉受害电脑："我是网关，我的MAC地址是 XXX"

↓

受害电脑把数据发给攻击者

↓

攻击者可以窃听、篡改数据

防范措施：使用静态 ARP 表、部署 ARP 检测工具

3. ICMP 协议（互联网控制报文协议）

3.1 什么是 ICMP？

ICMP（Internet Control Message Protocol，互联网控制报文协议）主要用于在
IP 网络中传递错误报告和诊断信息。

简单理解：ICMP
就像网络世界的"快递员"，负责报告"包裹送到哪了"、"出了什么问题"。

3.2 ICMP 的主要功能

     **功能**                **说明**                    **类比**

     差错报告          通知发送方数据包出错    快递员说\"地址不存在，退回\"

     网络诊断             测试网络连通性         打个电话确认对方是否在线

     超时通知             TTL 归零时通知        快递超时未送达，通知寄件人

3.3 ICMP 报文类型

   **类型编号**            **类型名称**              **说明**

         0                  Echo Reply              Ping 的回复

         3            Destination Unreachable       目标不可达

         8                 Echo Request             Ping 的请求

        11                 Time Exceeded           超时（TTL=0）

3.4 ICMP 的应用

ICMP 最常见的应用就是 Ping 和 Tracert/Traceroute 命令。

────────────────────────────────────────────────────────────

4. Ping 命令

4.1 什么是 Ping？

Ping 是基于 ICMP 协议的网络诊断工具，用来测试网络连通性。

名字来源：声纳探测时发出的"乒"声

4.2 Ping 的工作原理

发送方 → 发送 ICMP Echo Request（类型8）

↓

目标主机 → 回复 ICMP Echo Reply（类型0）

↓

发送方收到回复，计算往返时间（RTT）

4.3 Ping 的常用用法

# 基本用法
ping baidu.com

# 指定次数（Windows）
ping -n 4 baidu.com

# 指定次数（Linux/Mac）
ping -c 4 baidu.com

# 持续 Ping
ping -t baidu.com # Windows，按 Ctrl+C 停止

4.4 如何看懂 Ping 结果

C:\> ping baidu.com

正在 Ping baidu.com [39.156.66.10] 具有 32 字节的数据:
来自 39.156.66.10 的回复: 字节=32 时间=8ms TTL=52
来自 39.156.66.10 的回复: 字节=32 时间=7ms TTL=52
来自 39.156.66.10 的回复: 字节=32 时间=8ms TTL=52
来自 39.156.66.10 的回复: 字节=32 时间=7ms TTL=52

39.156.66.10 的 Ping 统计信息:
数据包: 已发送 = 4，已接收 = 4，丢失 = 0 (0% 丢失)，
往返行程的估计时间(以毫秒为单位):
最短 = 7ms，最长 = 8ms，平均 = 7ms

关键指标解读：

     **指标**                    **含义**                 **正常范围**

    时间(time)               往返延迟（RTT）         \< 30ms 优秀，\< 100ms
                                                              良好

        TTL            生存时间（经过的路由器跳数）    不同系统默认值不同

      丢失率                     丢包比例                0% 正常，\> 5%
                                                         说明网络有问题

4.5 Ping 不通的可能原因

  • ❌ 目标主机已关机或离线

  • ❌ 防火墙阻止了 ICMP 协议

  • ❌ 网络连接断开

  • ❌ 域名解析失败（DNS 问题）

  • ❌ 路由不可达

5. DNS（域名系统）

5.1 什么是 DNS？

DNS（Domain Name System，域名系统）的作用是：把人类易记的域名（如
baidu.com）转换成机器能识别的 IP 地址（如 39.156.66.10）。

举个 ：

  • 你想去"百度"（域名），但出租车司机只认"北京市海淀区上地十街10号"（IP地址）

  • DNS 就是那个"地址翻译官"

5.2 为什么需要 DNS？

没有 DNS 的世界：

  • 你要记住每个网站的 IP 地址：

  • 百度：39.156.66.10

  • 谷歌：142.250.80.46

  • 淘宝：140.205.94.189

  • ... 这太痛苦了！

有 DNS 的世界：

  • 你只需要记住：

  • baidu.com

  • google.com

  • taobao.com

  • DNS 自动帮你翻译成 IP 地址 ✓

5.3 DNS 查询过程

你在浏览器输入 www.baidu.com

↓

① 浏览器先查 本地DNS缓存（之前查过的记录）

↓ 没找到

② 浏览器查 本地hosts文件（C:\Windows\System32\drivers\etc\hosts）

↓ 没找到

③ 向 本地DNS服务器（通常是你的路由器或ISP提供的）发起查询

↓

④ 本地DNS服务器 开始递归查询：

↓

问 根域名服务器：".com 的服务器在哪？"

↓ 得到 .com 顶级域名服务器地址

问 .com 顶级域名服务器："baidu.com 的服务器在哪？"

↓ 得到 baidu.com 的权威域名服务器地址

问 baidu.com 权威域名服务器："www.baidu.com 的IP是多少？"

↓ 得到 IP: 39.156.66.10

⑤ 本地DNS服务器 把结果返回给你的电脑

⑥ 你的电脑 缓存这个结果（下次直接查缓存）

⑦ 浏览器 用 IP 地址访问百度

5.4 DNS 记录类型

   **记录类型**               **说明**                **示例**

       A记录              域名 → IPv4地址            baidu.com →
                                                    39.156.66.10

     AAAA记录             域名 → IPv6地址            baidu.com →
                                                   2400:da00::666

     CNAME记录                 域名 →              www.baidu.com →
                         另一个域名（别名）           baidu.com

      MX记录               邮件服务器地址           \@baidu.com →
                                                   mail.baidu.com

      NS记录               域名服务器地址            baidu.com →
                                                    ns1.baidu.com

      TXT记录          文本信息（常用于验证）    用于域名所有权验证

5.5 常用 DNS 服务器

**DNS服务商**      **首选DNS**       **备用DNS**          **特点**

   114DNS        114.114.114.114   114.114.115.115      国内，速度快

   阿里DNS          223.5.5.5         223.6.6.6          国内，稳定

   腾讯DNS        119.29.29.29           ---                国内

 Google DNS          8.8.8.8           8.8.4.4       全球，但国内可能慢

 Cloudflare          1.1.1.1           1.0.0.1            注重隐私

5.6 DNS 相关命令

# 查看 DNS 缓存（Windows）
ipconfig /displaydns

# 清除 DNS 缓存（Windows）
ipconfig /flushdns

# 使用 nslookup 查询域名
nslookup baidu.com

# 使用 dig 查询域名（更详细）
dig baidu.com

5.7 DNS 常见问题

     **问题**                **现象**              **解决方法**

      DNS劫持          访问A网站却跳到B网站        更换DNS服务器

    DNS缓存污染          域名解析到错误IP           清除DNS缓存

     DNS解析慢             打开网页很慢            更换更快的DNS

   DNS服务器宕机         无法访问任何网站           配置备用DNS

6. CDN（内容分发网络）

6.1 什么是 CDN？

CDN（Content Delivery
Network，内容分发网络）是一种通过在各地部署服务器，把内容"缓存"到离用户最近的节点，从而加速访问的技术。

举个 🌰：

  • 你在北京，想看一个视频

  • 视频源文件存在广州的服务器上

  • 如果没有 CDN：数据要从广州→北京，距离远，速度慢

  • 如果有 CDN：北京本地就有缓存节点，直接从北京获取，速度快很多！

6.2 CDN 的工作原理

用户访问 www.example.com

↓

① 用户向 本地DNS 查询 www.example.com 的 IP

↓

② 如果网站使用了 CDN，DNS 返回的不是真实服务器 IP

而是 CDN 的 智能调度系统 的 IP

↓

③ 智能调度系统 根据用户的地理位置、网络状况等

返回一个"离用户最近"的 CDN 节点 IP

↓

④ 用户直接访问这个 CDN 节点

↓

⑤ CDN 节点：

- 如果有缓存的内容 → 直接返回给用户（命中）

- 如果没有缓存 → 去源服务器获取，缓存后再返回（回源）

6.3 CDN 的核心优势

     **优势**                 **说明**                **效果**

    🚀 加速访问             就近获取内容        加载速度提升 50%-80%

    🌍 负载均衡          分散请求到多个节点         避免单点过载

     🛡️ 防攻击           分散 DDoS 攻击流量         保护源服务器

    📦 节省带宽           缓存减少回源请求         降低服务器成本

     🔄 高可用         某个节点挂了，自动切换        服务不中断

6.4 CDN 的应用场景

     **场景**                **举例**                  **说明**

   静态资源加速          图片、CSS、JS文件           最常见的用法

   视频点播/直播         抖音、B站、爱奇艺     视频文件大，需要就近分发

     下载加速           软件更新、游戏下载           大型文件分发

     动态加速            API接口、动态页面           优化网络路由

     全站加速                整个网站                动静结合加速

6.5 知名 CDN 服务商

    **服务商**               **类型**                **特点**

    Cloudflare                 国际             免费CDN，安全防护强

      Akamai                   国际              老牌CDN，节点最多

     阿里云CDN                 国内             国内节点多，速度快

     腾讯云CDN                 国内              与微信生态整合好

     网宿科技                  国内                 老牌国内CDN

6.6 CDN 相关概念

  • 回源：CDN节点没有缓存时，去源服务器获取数据

  • 预热：提前把内容推送到CDN节点（常用于大促活动前）

  • 刷新：强制清除CDN节点的缓存（更新内容后使用）

  • 边缘节点：离用户最近的CDN服务器

  • 命中率：用户请求在CDN节点直接获取的比例（越高越好）

7.1 各协议/技术对比

7.2 数据访问完整流程

你在浏览器输入 www.baidu.com 并回车

↓

① DNS解析：www.baidu.com → 39.156.66.10

（如果用了CDN，会解析到最近的CDN节点IP）

↓

② 建立TCP连接（三次握手）

↓

③ 发送HTTP请求

↓

④ 如果用了CDN：

- CDN节点有缓存 → 直接返回

- CDN节点无缓存 → 回源获取

↓

⑤ 服务器返回网页数据

↓

⑥ 浏览器渲染页面

↓

⑦ 你看到了百度首页 🎉

问题：网页打不开

↓

↓ 不通

② Ping IP地址（跳过DNS，检查网络连通性）

↓

⑤ 联系网络管理员/运营商

8. 常见面试题

Q1: ARP 和 DNS 有什么区别？

                              **ARP**                 **DNS**

       作用                IP → MAC地址            域名 → IP地址

     工作范围                局域网内               整个互联网

     协议层级                 网络层                  应用层

       缓存                  ARP缓存表                DNS缓存

Q2: Ping 不通一定是网络问题吗？

不一定。可能的原因：

  • 目标主机开启了防火墙，禁用了 ICMP

  • 目标主机已关机

  • 网络确实不通

  • DNS 解析失败（域名拼写错误）

Q3: CDN 和 DNS 有什么关系？

CDN 依赖 DNS 来实现智能调度：

  • 网站使用 CDN 后，DNS 记录会指向 CDN 的调度系统

  • DNS 解析时，CDN 的智能 DNS 会根据用户位置返回最近的节点 IP

  • 所以 CDN 和 DNS 是"合作"关系

Q4: 什么是 TTL？

TTL（Time To Live）有两个含义：

     **场景**                **含义**                   **作用**

       IP包                  最大跳数          防止数据包在网络中无限循环

      DNS缓存               缓存有效期         控制DNS记录在本地缓存的时间

Q5: 为什么有时候改了 DNS 设置后要清除缓存？

因为电脑会缓存之前的 DNS 解析结果。如果不清除缓存：

  • 即使换了新的 DNS 服务器

  • 电脑还是会用旧的缓存结果

  • 导致域名解析不到正确的 IP

所以改 DNS 后，建议执行：

ipconfig /flushdns
