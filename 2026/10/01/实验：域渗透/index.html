实验：域渗透

域渗透

1、概念和原理

1.1中继委派

中继： 钓鱼欺骗

委派： 以机器用户的身份去访问某台设备（在dc上进行），叫做委派访问，若配置不当，则可能让用户以任意机器任意身份去访问sql server

而我们这是进行窃取机器用户的身份，来窃取域中的一个访问权限

为什么用 HTTP 而不是 SMB 中继：Server 2016+ 默认启用 SMB 签名，SMB→LDAP 的 NTLM Relay 会被 MIC 校验阻断。mitm6 把目标诱导到 HTTP（WPAD 代理配置下载），HTTP 层没有 SMB 签名，NTLM blob 可以干净地中继到 DC 的 LDAP。

RBCD（基于资源的约束委派）：把目标 WebServer 机器账户的 msDS-AllowedToActOnBehalfOfOtherIdentity 属性写成受控的 Win10 机器账户（DESKTOP-BINE7L8$）。之后用该机器账户 hash 走 S4U2Self（以任意用户名义向 KDC 要一张到 WebServer 的票据）+ S4U2Proxy（形状转换），就能伪造 administrator 访问 WebServer，无需任何密码。机器账户修改自身对象属性属于 SELF 权限，天然合法。

5.启动中继

确认 banner 是 Impacket v0.13.0 而不是 v0.14.0.dev0，否则就是版本混装（见 6.1 版本坑条）。

参数说明：

参数 含义
-6 监听 IPv6（配合 mitm6）
-t ldap://192.168.41.131 中继目标：DC 的 LDAP
--delegate-access 拿到认证后执行委派攻击（配置 RBCD）
--escalate-user 'DESKTOP-BINE7L8$' 指定已存在的机器账户做委派源（绕开 TLS 建账户）
-smb2support 支持 SMB2 客户端（注意会占用 445）
--http-port 80 WPAD 假代理服务器监听 80
-wh wpad.saionjisekai.org WPAD 主机名

注意：中继全程经默认 proxychains 配置（socks5 127.0.0.1 1080）走 1080 隧道（WebServer 自身 frpc 注册的 SOCKS5），LDAP 报文从 WebServer 出去到达 DC。

6.触发认证，确认委派写入

  1. 重启 WebServer（或重启其网卡）——触发 DHCPv6 Solicit + WPAD 查询。
  2. 观察两个终端日志：
  1. 验证 RBCD 配置生效：msDS-AllowedToActOnBehalfOfOtherIdentity 已写入 DESKTOP-BINE7L8$ 的 SID，即 Win10 机器账户可以代表任意用户向 WebServer 委派。

注意：日志中还会看到 DESKTOP-BINE7L8$（Win10 自身）的 HTTP 认证被中继，属正常现象（无效操作被忽略）。要等到 WIN-VMCDN5AMRDJ$（WebServer 机器账户）的认证出现才算成功。
若重启后长时间无认证：再重启网卡或让 WebServer 访问任意网站，触发 WPAD 查询。
抢跑坑（必修）：单 -t 目标只有一次被写委派的机会。如果 WS 上有人开着浏览器，用户态浏览器的 SVC_WEB 认证会先中继成功、把唯一目标”耗尽”，之后的机器账户请求只会得到 no more targets left，那一次重启就白费了（日志里 All targets processed! 越多越说明被抢跑）。正确顺序：先关掉 WS 上所有浏览器 → 再重启 relay（清空目标）→ 再重启 WS，让开机阶段 SYSTEM 服务的机器账户认证第一个进来。
