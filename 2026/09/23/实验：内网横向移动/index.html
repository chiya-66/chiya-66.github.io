实验：内网横向移动

1.概念和原理

1.1 前置知识

这两个概念贯穿整个横向移动，先搞清楚再往下看。

1.1.1 NTLM vs Kerberos — Windows 的两种认证方式

一句话：NTLM 像对暗号

  • 全程没有传密码，只传了一个 Hash 加密后的响应值
  • 所以你有 Hash = 你能算出正确答案 = 你能认证——这就是 PtH 的前提
  • NTLM 还有一个弱点：挑战-响应可以被中继转发（NTLM Relay），你让受害机器替你答题

Kerberos：先去 KDC 换登机牌（TGT），之后一路畅通。

  • 密码/Hash 只在第①步用了一次，之后全程靠票据流转
  • 票据有有效期、绑定特定服务——没法像 NTLM 那样中继
  • Overpass the Hash 就是：用 NTLM Hash 做完第①步拿到 TGT，之后就切到 Kerberos 了

1.1.2 Pass the Hash (PtH) — 用 Hash 代替密码

原理： NTLM 认证中参与运算的是 Hash 本身，不是密码。只要你有目标的 NTLM Hash，就能算对 Challenge Response，服务器照样认。

哪些工具支持 PtH？

类别 工具 参数 需要明文？
Kali impacket wmiexec / psexec / smbexec / atexec -hashes :NTLM 否
Kali evil-winrm evil-winrm -H NTLM 否
Kali smbclient smbclient --pw-nt-hash NTLM 否
