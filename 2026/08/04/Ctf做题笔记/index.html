【HNctf2026】include

这个网站有一个”模板预览”功能，你可以在网址后面加 ?file=pages/home.php 来切换显示不同的页面。但它有个漏洞——它可以读取服务器上的任何 PHP 文件。

网站做了哪些防护？

网站怕被人乱搞，加了三个限制：

  1. 文件名必须以 .php 结尾 — 防止读取密码文件等非 PHP 文件
  2. 不能有 .. — 防止你返回上级目录
  3. 不能有 :// — 防止你用 php://、file:// 等特殊协议

那黑客是怎么绕过的？

黑客发现服务器上有一个”隐藏工具”叫 pearcmd.php，它在 /usr/local/lib/php/pearcmd.php 这个位置。

这个工具是干嘛的？ 它是 PHP 自带的”软件管家”，用来安装 PHP 扩展包的。本来是在命令行用的。

为什么它能用？ 因为它本身就是一个 .php 文件，路径里没有 .. 也没有 ://，所以三个限制都通过了！

具体怎么搞？

第1步：让”软件管家”帮我们写一个文件

这句话的意思是：

  • file=...pearcmd.php → 让网站加载这个”软件管家”
  • config-create → 告诉软件管家：”帮我创建一个配置文件”
  • <?=scandir("/");?> → 配置文件的内容是一段 PHP 代码，功能是”列出根目录下所有文件”
  • /tmp/ls.php → 把这个配置文件保存到 /tmp/ls.php

第2步：查看刚才生成的文件

网站加载 /tmp/ls.php，里面的 PHP 代码就会执行，显示出根目录下有哪些文件。这时候就能看到有一个叫 /flag 的文件。

第3步：读取 flag 文件

这次让”软件管家”再写一个文件，内容是”读取 /flag 文件的内容”。

第4步：查看 flag

网站加载 /tmp/flag.php，里面的代码执行，显示出 flag 的内容。

总结

网站只检查了 file= 这个参数是否合法，但没检查后面跟着的其他参数。黑客利用这个疏忽，通过 PHP 自带的”软件管家”工具，把恶意代码写入到服务器上，然后再加载执行，最终拿到了 flag。

知识点补充

VM2原理

VM2基于VM，使用官方的VM库构建沙箱环境。然后使用JavaScript的Proxy技术来防止沙箱脚本逃逸。

vm2 特性

1.运行不受信任的JS脚本
2.沙箱的终端输出信息完全可控
3.沙箱内可以受限地加载modules
4.可以安全地向沙箱间传递callback
5.死循环攻击免疫 while (true) {}

[Dest0g3 520迎新赛]EasyPHP

本题直接将源码暴露出来

大致内容有以下这些：

  • 从post参数ctf中获取用户输入

  • 判断当前时间（即返回当前小时，日期以及分钟），如果时间条件成立即大于24小时，大于31日，大于60分钟，即可条件成立，即获取flag；

  • 注册自定义错误处理函数，触发错误时打印出flag

关键知识点：

  • set_error_handler() 可以注册一个自定义函数，当 PHP 发生错误时自动调用

  • use (&$fl4g) 表示闭包通过引用捕获 $fl4g 变量，可以访问到它的值

  • .= 操作符 是字符串拼接

  • 在 PHP 中，字符串 . 数组 会触发一个 Notice 级别 的错误,这个错误会被 set_error_handler 注册的函数捕获，于是错误处理函数执行 print $fl4g，将 flag 打印出来。

所以，我们可以通过此思路，让以post参数ctf中获取的输入为一个数组即可
