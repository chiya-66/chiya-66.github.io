XXE 漏洞详解

一、XXE 漏洞定义

1.1 什么是 XXE

XXE（XML External Entity Injection）全称为 XML 外部实体注入。由于程序在解析输入的 XML 数据时，解析了攻击者伪造的外部实体而产生漏洞。

XML 是指可扩展标记语言，设计用于弥补 HTML 的不足，以强大的扩展性满足网络信息传输的需要，主要用于网络数据的转换和描述。

1.2 XML 基础知识

所有 XML 文档（以及 HTML 文档）均由以下构建模块组成：

构建模块 说明
元素（Element） XML 及 HTML 文档的主要构建模块，可包含文本、其他元素或空白内容
属性（Attribute） 提供有关元素的额外信息
实体（Entity） 用来定义普通文本的变量，实体引用是对实体的引用
PCDATA 被解析的字符数据（Parsed Character Data），会被解析器检查实体及标记
CDATA 不应由 XML 解析器进行解析的文本数据（Unparsed Character Data）

1.3 实体的概念

正常实体用于简化书写，类似于电脑中的快捷方式。例如，若想在 XML 中反复使用「你好，欢迎访问」，可以先定义一个实体：

关键点： XML 还支持外部实体，即让实体指向电脑里的文件或网络地址——这就是 XXE 漏洞的根源！

1.4 漏洞成因

利用外部实体的特点，攻击者可以通过 XXE 漏洞：

  • 读取服务器的敏感文件和本地配置文件
  • 联动 SSRF 攻击内网服务
  • 拒绝服务攻击（Billion Laughs 攻击）

二、XXE 漏洞原理

2.1 有回显 XXE

当服务器将 XML 解析结果直接返回给客户端时，攻击者注入的实体内容（即读取到的文件内容）会直接显示在响应页面中。

flowchart LR
    A[攻击者] -->|1. 注入 XXE Payload| B[靶机服务器]
    B -->|2. 解析 XML\n读取本地文件| C[(本地文件 / 配置文件)]
    C -->|3. 文件内容| B
    B -->|4. 响应中回显文件内容| A

2.2 无回显 XXE（Blind XXE）

当服务器启用了防御措施（如禁用实体回显），攻击者无法直接从响应中获取文件内容。此时需要借助一台恶意服务器（OOB 带外数据通道）来接收数据。

flowchart LR
    A[攻击者] -->|1. 注入 XML 模板\n引用外部 DTD| B[靶机服务器]
    B -->|2. 加载 vil.dtd| C[恶意服务器]
    C -->|3. 返回 DTD 内容| B
    B -->|4. 解析 DTD\n读取本地文件\nBase64 编码| D[(本地文件)]
    D -->|文件内容| B
    B -->|5. 将文件内容发送至 get.php| C
    C -->|6. 写入 file.txt| E[(file.txt)]
    A -->|7. 查看 file.txt| E

三、XXE 攻击实战

3.1 场景一：直接读取本地文件（有回显）

攻击步骤

  1. 使用 Burp Suite 抓包，将请求发送到 Repeater（重放器）
  2. 构造包含外部实体的 XML Payload
  3. 发送请求，观察响应中是否回显文件内容

无防护 XML 模板

实战 Payload 示例

Payload 逐行详解

代码片段 说明
<?xml version="1.0"?> 标准 XML 头部，告诉服务器这是 XML 格式，必须存在，否则解析失败
<!DOCTYPE test [...]> 文档类型声明（DOCTYPE），用来定义实体，是 XXE 的核心入口；test 为自定义根节点名，可随意命名
<!ENTITY file SYSTEM "file:///etc/passwd"> 定义名为 file 的实体（变量）；SYSTEM 表示外部实体，加载外部资源；file:///etc/passwd 使用 file 协议读取 Linux 密码文件
<user>&file;</user> &file; 调用实体，服务器解析时将文件内容替换到此处，页面直接回显

提示： 读取 Windows 系统文件时，将路径替换为 file:///c:/windows/win.ini。之后可直接读取 flag，或使用 Base64 转码后读取。

3.2 场景二：登录框场景

在实际渗透测试中，很多 Web 应用的登录功能使用 XML 格式传输数据。通过抓包可以发现请求体中包含 XML 模板，进而确认 XXE 漏洞是否存在。

flowchart LR
    A[登录框] -->|输入用户名密码\n点击登录| B[Burp Suite 抓包]
    B -->|发现 XML 格式请求体| C[修改 XML 模板]
    C -->|注入 XXE Payload| D[靶机服务器]
    D -->|响应回显文件内容| E[确认 XXE 漏洞存在]

攻击步骤

  1. 正常登录抓包：在登录框输入用户名和密码，使用 Burp Suite 拦截请求
  2. 观察请求体：查看请求体是否为 XML 格式（如 <user><name>admin</name></user>）
  3. 注入 Payload：将原始 XML 修改为包含外部实体的 Payload
  1. 查看响应：如果响应中返回了 /etc/passwd 的内容，则确认 XXE 漏洞存在

3.3 场景三：无回显 XXE（Blind XXE）

当服务器对 XXE 进行了防御（如禁用回显），注入 Payload 后响应中不会显示文件内容。此时需要使用 OOB（Out-of-Band）带外数据通道，通过恶意服务器来接收读取到的数据。

攻击环境准备

在恶意服务器（如虚拟机中的 phpStudy）上准备以下文件：

文件 作用
vil.dtd 恶意 DTD 文件，定义参数实体来读取文件并发送数据
get.php 接收数据的 PHP 脚本，将数据写入 file.txt
file.txt 存储最终读取到的文件内容（由 get.php 自动创建）

vil.dtd —— 恶意 DTD 文件

逐行解析：

行 代码 说明
1 <!ENTITY % file SYSTEM "php://filter/..."> 定义参数实体 %file，使用 php://filter 协议读取靶机上的 hosts 文件并进行 Base64 编码（避免文件中的特殊字符导致 XML 解析错误）
2 <!ENTITY % all "<!ENTITY &#x25; send SYSTEM '...'>"> 定义参数实体 %all，其值为另一个实体定义。使用 &#x25;（% 的 HTML 实体编码）嵌套定义 %send 实体，因为 XML 不允许在实体值中直接嵌套参数实体引用
3 %all; 调用 %all 实体，实际效果是定义了 %send 实体
4 %send; 调用 %send 实体，触发 HTTP 请求，将文件内容作为参数发送到 get.php

注意： 192.168.75.204 是恶意服务器（攻击机）的 IP 地址，需根据实际情况修改。resource= 后面的路径是靶机上要读取的目标文件路径。

完整攻击流程

flowchart TD
    subgraph 攻击机/恶意服务器
        V[vil.dtd<br/>恶意 DTD 文件]
        G[get.php<br/>数据接收脚本]
        F[(file.txt<br/>最终数据)]
    end

    A[攻击者] -->|1. 在靶机注入 XML 模板| T[靶机服务器]
    T -->|2. 解析 XML\n远程加载 vil.dtd| V
    V -->|3. 返回 DTD 内容| T
    T -->|4. 执行 DTD 中的指令\n读取本地文件\nBase64 编码| L[(靶机本地文件)]
    L -->|文件内容| T
    T -->|5. HTTP 请求发送文件内容\n到 get.php?file=...| G
    G -->|6. 写入数据| F
    A -->|7. 查看 file.txt\nBase64 解码| F

分步说明：

  1. 攻击者在靶机上注入经过修改的 XML 模板（引用 http://攻击机IP/vil.dtd）
  2. 靶机解析 XML 时，远程加载恶意服务器上的 vil.dtd
  3. vil.dtd 返回给靶机后，靶机开始执行其中的指令
  4. vil.dtd 中的 %file 实体使用 php://filter 读取靶机本地文件并进行 Base64 编码
  5. %send 实体触发 HTTP 请求，将编码后的文件内容发送到 get.php?file=...
  6. get.php 接收数据，写入 file.txt
  7. 攻击者查看 file.txt，将 Base64 内容解码即可获得原始文件内容

五、防御措施

防御方式 说明
禁用外部实体 在 XML 解析器中禁用外部实体加载（如 PHP 中设置 libxml_disable_entity_loader(true)）
使用 JSON 替代 XML 优先使用 JSON 格式传输数据，避免 XML 解析风险
输入校验 对用户输入进行白名单校验，过滤 DOCTYPE、ENTITY 等关键字
最小权限 Web 服务运行账户使用最小权限，限制可读取的文件范围
