文件上传漏洞

一、文件上传的大致定义

文件上传功能本身是正常的业务需求（如头像上传），但当开发者未对文件类型、内容、文件名做严格校验时，攻击者就可以上传恶意脚本（如 PHP、JSP、ASP），通过该脚本获取服务器控制权。

核心条件：上传目录可访问 + 文件可被服务器解析。

二、验证文件类型的分类

  1. 前端 JS 校验文件后缀名
  2. 后端校验：
    • 校验文件后缀名
    • 校验 MIME 类型（HTTP 请求头里的一段文字，告诉服务器”我传的是什么类型”）
    • 校验文件头类型（文件本身最开头的一串二进制，代表文件真实类型）

三、文件上传的漏洞分类

2. 后端校验

MIME 类型校验漏洞

  • 防护原理：后端仅校验 HTTP 请求头中的 Content-Type 字段，不校验文件后缀和内容。
  • 核心特征：上传 .php 文件被拦截，上传 .jpg/.png 正常，抓包可见 Content-Type 字段。
  • 绕过方法：抓包修改 Content-Type 为 image/jpeg、image/png、image/gif。
  • 靶场对应：Upload-Labs Pass-02
  • 备注：仅校验请求头，极易绕过，实战中较少单独出现。

后缀黑名单校验漏洞

  • 防护原理：服务器列出禁止上传的脚本后缀黑名单（如 .php、.asp、.jsp）。

  • 核心特征：提示”禁止上传 php 等脚本文件”，非黑名单后缀可上传。

  • 绕过方法：

    方式 说明
    特殊后缀 .php3/.php4/.php5/.phtml（Apache 解析）
    大小写绕过 .pHp/.PHP（Windows 环境生效）
    特殊符号 .php （空格）、.php.（末尾点）、.php;jpg、php. .
    空字节截断 .php%00.jpg（PHP < 5.3.4），详见下方说明
    ::$DATA 绕过 Windows 文件流特性，抓包在后缀后加 ::$DATA（建立连接时需删除）
    双写绕过 有些服务器会将黑名单后缀删除，可使用双写（如 .pphphp）绕过

    %00 截断详解：

    %00 是 URL 编码的空字节（null byte，即 0x00）。C 语言以 \0 作为字符串结束符，而 PHP 底层由 C 实现，在 PHP < 5.3.4 版本中，文件操作函数（如 move_uploaded_file）遇到空字节会截断字符串。

    以 shell.php%00.jpg 为例：前端校验看到的是 .jpg 后缀，通过校验；服务端 URL 解码后变为 shell.php\0.jpg，C 函数读取时在 \0 处截断，文件被保存为 shell.php。访问时直接访问 shell.php 即可，无需手动删除后缀（截断已在服务端保存时完成）。

    • GET 型：%00 在 URL 参数中，会被服务器自动 URL 解码为空字节。例如 ?save_path=../upload/shell.php%00，服务端截断后保存为 shell.php。
    • POST 型：参数在请求体中，直接写入 %00 可能被当作普通字符串，需要用 Burp Suite 的 URL 解码功能将 %00 转换为真实的 0x00 字节，再发送请求。

    前提条件：PHP < 5.3.4，且 magic_quotes_gpc 为关闭状态。

  • 靶场对应：Upload-Labs Pass-03/05/06

  • 备注：最常见的上传漏洞类型，绕过方式最多。

后缀白名单校验漏洞

  • 防护原理：仅允许指定后缀（如 .jpg/.png/.gif），其余后缀全部拒绝。

  • 核心特征：只有白名单内文件可上传，脚本后缀一律拦截，防护性较强。

  • 绕过方法：

    a. %00 截断

    与黑名单中的 %00 截断原理相同。白名单只校验后缀是否为 .jpg，但通过 %00 截断使服务端实际保存为 .php。例如：shell.php%00.jpg，前端看到 .jpg 通过白名单，服务端截断后保存为 shell.php。

    注：白名单场景下 %00 通常出现在保存路径参数中（如 save_path=../upload/shell.php%00），而非文件名本身。

    b. 路径截断

    在文件路径后添加 / 或 /.，如 shell.php/.。某些情况下系统会将 / 前面当做文件名、后面当做目录，从而将 shell.php 当做可执行脚本。

    c. 配合文件包含漏洞执行图片马

    命名时使用正常图片的命名方式（如 muma.jpg），文件内容则带有 PHP 指令，然后通过文件包含漏洞来激活执行（详见”文件包含漏洞”小节）。

    d. 路径修改

    上传路径就是服务器把上传文件最终”存到哪个文件夹、叫什么名字”的位置。路径可控漏洞则是可以自己改路径，想存到哪儿就存到哪儿，从而把图片修改为 PHP 脚本，最终让服务器去执行木马。

    操作：通过抓包修改第 1 行的路径，使系统通过 .jpg 文件验证的同时将其以 PHP 脚本运行（结合 %00 截断）。

文件包含漏洞

  • 原理：未对包含的文件进行过滤，从而可以随意包含任意一个文件，包括带脚本的木马文件。文件包含函数（如 PHP 的 include、require）会将所包含文件的内容当作 PHP 代码执行，因此即使图片马后缀为 .jpg/.png，只要被包含就会触发其中的木马代码。

  • 利用方法：首先找到一个可以操作的文件包含点位（靶场中可在根目录创建带木马的文件，实战中则通过 http(s) 协议将木马注入到一个文件中），然后依照路径访问该点位，从而让木马自动运行。

配合文件包含执行上传的图片马

上传图片马成功后，图片本身只是被当作普通图片存储，无法直接执行其中的 PHP 代码。此时需要找到一个文件包含漏洞点（通常是带 file、page、path 等参数的 URL），将图片马的路径作为参数传入，让服务端把它当作 PHP 代码包含并执行。

完整流程：

  1. 上传图片马：按上文方法制作图片马（如 webshell.png）并上传成功，记录上传后的保存路径。

  2. 确认上传路径：上传后服务器通常会返回保存路径。注意，很多服务器会对文件重命名（如使用时间戳、随机字符串等），例如上传 webshell.png 后实际保存为 1627891234.png，此时需从回显或抓包响应中获取真实文件名。

  3. 找到文件包含点：寻找形如 ?file=、?page=、?path= 的参数，该参数对应的页面调用了 include/require 等文件包含函数。

配置文件解析漏洞

  • 相关知识点：配置文件是服务器/PHP 的行为规则文件。攻击文件上传，本质就是在利用这些规则的漏洞。

条件竞争漏洞

  • 防护原理：服务器先临时保存文件，再校验，不合格则删除，存在时间差。

  • 核心特征：文件上传成功后瞬间被删除，无法正常访问。

  • 绕过方法：Burp Suite 多线程并发上传，同时高频访问文件路径，抢在删除前执行。

    具体操作步骤：

    1. 抓包：用 Burp Suite 抓取上传请求，右键发送到 Intruder（攻击模块）。
    2. 标记变量：在文件名 .php 后面加上 1（如 shell.php1），选中 1，点击”Add §”标注为变量。
    3. 设置 Payload：在 Payloads 选项卡中，Payload type 选择 Null payloads（空载荷，即不修改变量，保持原样无限重发）。
    4. 配置线程：在 Options 中设置较高线程数（如 20-50），加快并发速度。
    5. 开始攻击：点击 Start attack，Intruder 会持续并发发送上传请求。
    6. 同时访问：攻击发起后，同时在浏览器或用另一个 Intruder 持续高频访问 shell.php，抢在服务器删除临时文件之前触发执行，生成持久化木马。

  • 靶场对应：Upload-Labs Pass-17

  • 备注：考验并发操作，需持续发包抢占执行时机。

    由于服务器二次渲染会清除恶意代码，需要找到渲染后未被修改的区域插入木马。以 GIF 为例：

    1. 制作 GIF 图片马：先制作一个基础的 GIF 图片马（图片 + 一句话木马）。
    2. 上传图片马：将图片马上传到关卡中，服务器会对它进行二次渲染。
    3. 另存渲染后的图片：将服务器渲染后返回的图片另存到本地——这就是被二次渲染后的版本，从中可以对比找出哪些区域未被修改。

    6. 重新上传：保存修改后的 GIF 文件并重新上传，此时木马代码位于渲染未触及的区域，能够保留下来，配合文件包含漏洞即可执行。

    注： 关键在于对比上传前后的图片，找到二次渲染未修改的区域。不同格式（GIF/PNG/JPG）的渲染区域不同，需分别分析。GIF 通常在帧数据间隙有可利用空间。

中间件解析漏洞

  • 防护原理：Web 服务器（IIS/Nginx/Apache）自身解析规则缺陷，非脚本后缀可被解析。

  • 核心特征：上传正常图片文件，构造特殊文件名/路径可执行脚本。

  • 绕过方法：

    中间件 绕过方式
    IIS 6.0 shell.asp;.jpg、/shell.asp/1.jpg
    Nginx/IIS 7.5 shell.jpg/.php
    Apache shell.php.xxx（多后缀解析，从右往左解析直到遇到可识别后缀）

  • 靶场对应：Upload-Labs Pass-19/20

  • 备注：不属于代码漏洞，是中间件自身缺陷，实战中高频利用。

四、速查使用技巧

  1. 做题时先看拦截特征（如抓包查看、数据回显上传成功等），对应表格找漏洞类型，再用对应绕过方法。

  2. 实战中先测试前端、MIME、黑名单，再测试白名单、内容检测，最后尝试中间件漏洞。上传木马后务必确认上传路径，无路径则无法执行木马。

  3. 上传成功后，想要 getshell 必须满足：文件能正常被访问到，且文件能被服务器当做脚本解析并运行。
